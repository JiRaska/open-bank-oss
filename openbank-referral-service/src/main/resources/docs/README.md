# OpenBank Referral Service

Manages referral programs and their customer participation.

## Interface

The committed `src/main/resources/openapi.yaml` defines the API contract. Read `/q/openapi` on the running service for the exact paths, request bodies, responses, and contract version of its image.

## Build identity

The generated `00-build` page in this same documentation index reports the release version, full source commit, and API contract version packaged in the running image. The index is available at `/q/openbank/docs`.

## Shared build dependencies

This service's `build.gradle.kts` does not list the dependencies every Quarkus service shares: the Quarkus BOM, quarkus-kotlin, RESTEasy Reactive with Jackson, SmallRye Health and OpenAPI, OIDC, the Micrometer Prometheus registry and config-yaml, plus the quarkus-junit5, AssertJ and REST Assured test libraries. The `openbank.quarkus-service` convention plugin in `build-logic` declares them. The resolved classpath is unchanged. `build.gradle.kts` lists only what this service adds.

## Contract testing

Both sides of this service's event contracts are machine-checked:

- `AccountCreatedMessagePactConsumerTest` pins the `openbank.accounts.account.created` message
  contract that triggers qualification (ADR-0310 D1): the `AccountCreated` literal, `eventId` as
  opaque idempotency text, and `partyId` + `occurredAt` as the decision inputs.
- `ReferralEventPactFolderProviderVerificationTest` (and its broker twin) replays the
  `openbank.referral.qualified.v1` pact that loyalty-service consumes, producing the real
  `Qualified` event so a drift in the producer is caught before merge.

The generated pacts are committed to `pacts/` and regenerated by the consumer tests.
