# KYB ownership evidence

KYB owns versioned observations of mapped beneficial-owner findings for a business onboarding case. The source data remains in KYB; the dedicated Kafka event carries only an observation reference, case ID, revision and time. `sourceSha256` hashes KYB's serialized mapped finding. It is **not** a hash of the original register response, which is not retained here.

The additive API contract is in [`openapi.yaml`](../openapi.yaml). A KYC or admin operator may read an exact `/api/v1/kyb/cases/{id}/ubo-observations/{observationId}` only with purpose `KYB_OWNERSHIP_REVIEW`, a current approved Context case assignment and a successful source read audit. Denial is 403; an unavailable authorization service is 503. Responses are not cacheable. A case assignment does not permit browsing unrelated observations.

Corrections start with a fresh register lookup, not owner attributes supplied by the caller. A KYC or admin maker proposes a candidate against an exact prior observation; a different reviewer must read and audit that candidate before a decision. Approval links the new observation to its predecessor and emits its minimized reference in the same transaction. PostgreSQL guards reject a stale or restricted predecessor, a changed candidate, self-approval, and a missing successor. An admin can permanently restrict an observation after the same live case-scope check; restricted evidence must not reappear in Context history.

Flyway V13–V18 add observations, read audits, restrictions, correction proposals and reviewer evidence. Keep applied migrations immutable. A restriction or correction does not erase the append-only source history. The data-free Context access route is default-off (`openbank.kyb.data-free-context-access-enabled`); do not enable it until the dependent Context endpoint and deployed TLS/policy path are verified. The original register artifact and document-level provenance are still absent, so the mapped-finding digest must not be presented as proof of that artifact.
