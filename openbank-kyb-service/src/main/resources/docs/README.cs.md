# Důkazní historie skutečných majitelů v KYB

KYB vlastní verzovaná pozorování mapovaných zjištění o skutečných majitelích v případu firemního onboardingu. Zdrojová data zůstávají v KYB; vyhrazená Kafka událost nese jen referenci pozorování, ID případu, revizi a čas. `sourceSha256` je hash serializovaného mapovaného zjištění v KYB. **Není** to hash původní odpovědi registru, která se zde neuchovává.

Aditivní smlouva API je v [`openapi.yaml`](../openapi.yaml). Operátor s rolí KYC nebo admin smí číst přesné `/api/v1/kyb/cases/{id}/ubo-observations/{observationId}` pouze s účelem `KYB_OWNERSHIP_REVIEW`, platným schváleným přiřazením případu v Contextu a úspěšným auditem čtení ve zdrojové službě. Zamítnutí vrací 403, nedostupná autorizační služba 503. Odpověď se nesmí cachovat. Přiřazení případu neopravňuje k procházení nesouvisejících pozorování.

Oprava vychází z nového čtení registru, nikoli z údajů o vlastnících zaslaných klientem. Operátor KYC či admin navrhne kandidáta vůči přesnému předchozímu pozorování; jiný posuzovatel musí kandidáta před rozhodnutím přečíst a toto čtení auditovat. Schválení v jedné transakci propojí nové pozorování s předchůdcem a odešle minimalizovanou referenci. PostgreSQL ochrany odmítají zastaralého nebo omezeného předchůdce, změněného kandidáta, vlastní schválení a chybějícího nástupce. Admin může pozorování trvale omezit po stejné kontrole živého přiřazení případu; omezený důkaz se nesmí znovu objevit v historii Contextu.

Flyway V13–V18 přidávají pozorování, audity čtení, omezení, návrhy oprav a důkaz o čtení posuzovatelem. Aplikované migrace neměň. Omezení ani oprava nemažou append-only zdrojovou historii. Přístupovou cestu Contextu bez předání dat ovládá výchozím stavem vypnutý přepínač `openbank.kyb.data-free-context-access-enabled`; zapni jej až po ověření závislého endpointu Contextu a nasazené TLS/policy cesty. Původní artefakt registru ani provenance na úrovni dokumentu zde stále nejsou, proto hash mapovaného zjištění nevydávej za důkaz původního artefaktu.
